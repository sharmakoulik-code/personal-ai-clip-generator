# Backend

The FastAPI API stores project, ingestion job, and video metadata in SQLite. Large files go into local storage, not the database. The default server command is:

```powershell
cd backend
..\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Install the dependencies in `requirements.txt` first. FFmpeg and FFprobe must be on PATH for video processing. `CLIP_DB_PATH`, `CLIP_STORAGE_PATH`, `CLIP_MAX_UPLOAD_BYTES`, `CLIP_FFMPEG` and `CLIP_FFPROBE` are optional backend-only settings. The API has no authentication: never expose it to an untrusted network. See the root README for Windows setup and validation limitations.

## Phase 3 analysis API and storage

Install the existing `requirements.txt` (Python 3.11+); it includes `faster-whisper==1.2.1`. FFmpeg and FFprobe are required as for ingestion. Default inference is CPU/int8, with optional `CLIP_WHISPER_DEVICE=cpu|cuda|auto`. Models are downloaded to `<CLIP_STORAGE_PATH>/models` or loaded from `models/whisper-{tiny,base,small,medium}`. CUDA requires a separately compatible NVIDIA runtime. See the root README for Windows use, downloading models, limitations and validation status.

- `POST /api/videos/{video_id}/analyze`: body `{ "model": "base", "duration_range": "15-30", "force_transcribe": false, "groq_titles": false, "gemini_titles": false, "cloud_titles": false }` (other ranges: `30-45`, `45-60`, `60-90`). Returns 202; at most one queued/running analysis per video.
- `GET /api/videos/{video_id}/analysis-jobs`, `GET /api/analysis/jobs/{id}`, `POST /api/analysis/jobs/{id}/cancel`: persistent job progress/state and cancellation.
- `GET /api/videos/{video_id}/transcription`: stored language, model, timed segments and word timestamps; 404 until available.
- `GET /api/videos/{video_id}/clips`: candidates with timestamps, title, hook, transcript, weighted scores and selection. `PATCH /api/clips/{id}` with `{ "selected": true }` updates one; `PATCH /api/videos/{video_id}/clips/selection` updates all.

`transcripts` stores the cached model/language and video link, `transcript_segments` stores text/timestamps and serialized word timestamps, `candidate_clips` stores suggested ranges/score breakdowns/selections, and `analysis_jobs` stores the queue, parameters, progress and failures. Foreign keys cascade on deletion; a partial unique index prevents duplicate active jobs per video. The single in-process worker marks interrupted running jobs failed on application startup and resumes queued jobs. Do not start multiple backend processes against the same storage. Results are atomically replaced only after successful analysis. With no recognized speech the job reports failure; videos with no audio stream are rejected before enqueue.

For optional real inference testing, set `CLIP_TEST_MODEL_DIR` to a converted Base model folder and `CLIP_TEST_SPEECH_VIDEO` to the JFK speech MP4 fixture before running `python -m pytest`. Without these, the real-model test is skipped. Normal model download from Hugging Face and CUDA remain environment-dependent and are not proven by this optional test.


`cloud_titles: true` opts into Cloud AI: try Groq first, then Google Gemini on a provider failure or missing key. Configure `GROQ_API_KEY` and `GEMINI_API_KEY` in the backend process to enable both. It sends candidate transcript excerpts to the selected provider(s), never the video; failures preserve prior results. `groq_titles` and `gemini_titles` remain available for older API clients to select a single provider. At most one of the three flags may be true. Startup adds the three flag columns to existing `analysis_jobs` tables. See the root README for Windows setup, privacy and limitations.


## Phase 4 rendering API

`opencv-python-headless` provides the bundled CPU Haar detector; FFmpeg/FFprobe must be on PATH and the FFmpeg build must support libx264 and AAC. Optional `CLIP_RENDER_ENCODER=nvenc` requests NVIDIA H.264 encoding without automatic fallback; default is `cpu`. This encoder and Phase 4 on Windows have not been validated. The standard detector only frames visible faces; the optional mouth-motion heuristic is not reliable speaker identification.

- `GET /api/videos/{id}/stream`: local source with HTTP range support.
- `GET /api/clips/{id}/render-preview`: representative JPEG at clip start, with `X-Framing-Status`; settings are query parameters.
- `POST /api/clips/{id}/render` or `POST /api/projects/{id}/render-batch`: 202 and persistent jobs. Batch includes selected clips across the project and accepts at most 100. Settings JSON: `{ "layout": "smart", "resolution": 1920, "quality": "balanced", "horizontal": 0, "vertical": 0, "zoom": 1, "track_faces": true, "detect_interval": 1, "split_ratio": 0.67 }`. Layout: `smart|center|blur|split`; resolution: `1280|1920` (portrait height); quality: `high|balanced|small`; offsets -1..1, zoom 1..2, interval .5..5 seconds, split ratio .5.. .8.
- `GET /api/renders?project_id={id}` or `?video_id={id}` and `GET /api/renders/{id}`: newest jobs and details (list limited to 200).
- `POST /api/renders/{id}/cancel`, `POST /api/renders/{id}/retry`, `DELETE /api/renders/{id}`; `GET /api/renders/{id}/stream` and `/download` for completed jobs.

The `renders` table snapshots clip ranges/settings and tracks progress and output paths; `face_track_cache` stores sampled crop centers. A partial unique index blocks two active renders for a clip. A single worker processes jobs, uses bounded-frame sampling and FFmpeg, validates output and moves it into local rendered storage. The first audio stream is retained if present. Pending work resumes after restart; interrupted jobs are marked failed, and cancelled/failed jobs can be retried if their source clip still exists. Video/project deletion and re-analysis are blocked by active renders. Source files and outputs are restricted to local storage paths. See root README for operational and Windows test instructions and limitations.

The smart layout additionally accepts `tracking_engine: "subject"`, `smooth_time` (.15–2 seconds), and `dead_zone` (0–.5); `standard` remains the default for existing clients. Subject mode samples faces and motion, builds a smoothed camera path, and reports the detector used in `tracking_status`. YuNet downloads on first subject render unless `CLIP_NO_MODEL_DOWNLOAD=1`; a SHA-256 verified model is cached under storage/models. If unavailable or unsupported, Haar is used and reported. This is visual framing, not speaker identification.

Subject tracking can opt into `active_speaker: true`. It merges existing word timings to locate speech, then heuristically compares mouth motion across associated faces with a switch delay and group framing. It reports `info.tracks`, `info.speaker_switches`, and `info.speaker_status`; without transcript words it reports `no_transcript` and uses visual tracking. This cannot reliably identify speakers in profile, at low resolution, with camera motion, overlapping voices or off-screen speech.


For optional padded cuts use `pad` (0–1 seconds; default 0); `normalize_audio: true` requests loudness normalization and changes the original audio levels. For burn-in, request `captions: true` with `caption_style: highlight|classic|minimal` and optional `caption_uppercase`. FFmpeg needs the `ass` filter; optional `CLIP_CAPTION_FONT` and `CLIP_CAPTION_FONTS_DIR` select locally installed fonts. Captions are generated from stored word timings, never from a cloud model. A missing timed transcript is an error. `GET /api/clips/{id}/captions.srt` downloads relative-time subtitles without burning them into video.

`POST /api/videos/{id}/analyze` accepts `selection_mode: local|llm` (default `local`). `llm` requires a Groq or Gemini environment key and supersedes title provider flags; bounded, overlapping numbered transcript excerpts and timings are sent to providers, never video. Provider responses suggest integer indices; the backend validates boundaries/durations, deduplicates, sanitizes text and blends local and AI scores. Groq uses its GPT-OSS structured-output schema and overlapping transcript windows of about 4,500 characters, requesting up to five clips and 3,072 output tokens per window to reduce per-request load; Gemini keeps its existing larger windows. Character counts are only a rough token estimate, especially across languages, and smaller windows can alter selections. Transient HTTP 408/500/502/503/504 and connection failures are retried up to twice per window. On HTTP 429, the app retries once after the provider’s Retry-After delay, or 30 seconds if absent/invalid; if the provider asks for over 60 seconds it falls back without retrying. Waits are cancellable. If Groq reports `json_validate_failed`, the app retries that window once and otherwise falls back; it never displays the failed generated text. If an HTTP failure persists, the UI reports a sanitized status code, never the provider response or keys. On total failure old clips/selections remain. Scores and titles are suggestions, not guarantees.

### Experimental Shorts framing

The existing render and preview endpoints also accept `layout: "auto" | "follow" | "fit_blur" | "stack"`. `follow` uses local subject tracking; `fit_blur` preserves the full frame over a dimmed, blurred background. `auto` estimates crop upscaling and chooses follow at 1.5× or less, otherwise fit-blur. Set `stack_two_speakers: true` to allow auto to choose a stack when two persistent tracks are visible. An explicit `stack` falls back to fit-blur if two tracks cannot be established; completed jobs include `info.layout_used`, `info.upscale_factor`, and any `info.layout_fallback_reason`. `fit_vertical_bias` (-.25 to .25, default -.05) adjusts placement and `sharpen` (0 to 1, default .35) controls conditional upscaling sharpening. Tracking is heuristic, and stacked framing can be unsuitable for scene changes or intermittent faces. Check the results manually, especially with scene cuts or intermittent faces.

### Experimental preflight and Shorts export

`GET /api/videos/{id}/preflight` returns locally sampled source checks. New imports run preflight before completion; older videos are checked on first request. Results are cached in `videos.preflight_json`, added at startup without replacing existing video rows. The warning codes are `already_vertical`, `low_resolution`, `too_short`, `no_audio`, `possible_burned_in_captions`, `no_faces_detected`, `high_cut_rate`, `variable_frame_rate`, `odd_frame_rate`, and `preflight_failed`. Caption, cut-rate, face and variable-frame-rate findings are heuristics, not guarantees. Warnings are shown in the project analysis and render panels; possible burned-in captions require an explicit `force_captions` override when burning captions.

The render API accepts **explicit** `preset: "shorts"`: 1080×1920 H.264/AAC, BT.709 tags, 48 kHz stereo and faststart. It rejects clips longer than 180 seconds, selects a frame rate without exceeding the source except for rates within 0.5% below a standard rate (for example, 29.97 → 30 fps), and attempts two-pass loudness normalization to `loudness_lufs` (default -14 LUFS, -30 to -5). If measurement fails it renders without normalization and reports a warning; output loudness is measured and warnings are returned when it misses the target. Source frame rates below 24 remain at the source rate unless they are within 0.5% of 24. FFmpeg preserves duration when normalizing near-standard rates, occasionally duplicating a frame. Requests without `preset` use the legacy encoder/resolution behavior for existing clients, rather than the specification's proposed default Shorts preset. The project UI enables the Shorts preset by default. Analysis accepts `duration_range` of `20-45`, `20-60`, or `20-180` in addition to existing ranges. Verify Shorts rules against YouTube's current documentation before publishing.

Hook-first selection now validates an optional `hook_sentence_index` against the locally timed units before moving a proposed start, and local scoring applies small greeting/complete-ending adjustments. For explicit `preset: "shorts"`, timed transcripts enable conservative filler and pause removal by default (`tighten: false` disables it, `trim_fillers: false` keeps leading fillers, `max_pause` controls the retained pause cap). Cuts are limited to 30% of the source range; video and audio are concatenated locally with short fades and burned captions use remapped timings. This is experimental; use a `render_id` when downloading captions to use the exact word timeline saved with that render.


### Shorts captions, review and metadata endpoints

- `GET /api/clips/{id}/captions.srt?render_id={render}` and `.vtt?render_id={render}` use the word timeline saved with that completed render. Without `render_id`, both use the current clip/transcript timeline for backward compatibility. Older completed renders without a timeline return 409 with a render ID. `caption_safe_zone` defaults true; `force_captions` explicitly overrides a possible burned-in-caption warning.
- `PATCH /api/clips/{id}` accepts optional `start`, `end`, and/or `selected`, with a 3–180 second trimmed range, and stores original boundaries; `POST /api/clips/{id}/revert` restores them. Render options `start_offset`, `end_offset` (±5 seconds), `x_offset`, and `y_offset` (±.35 crop dimensions) are locally clamped. Existing untrimmed clips under 3 seconds remain renderable when no offsets are applied.
- `GET /api/clips/{id}/preview-path` uses render settings as query parameters and returns source dimensions, chosen layout and source-pixel crop coordinates at roughly 10 Hz. Paths are cached in a bounded in-memory cache. For stack mode the representative overlay is the first panel; inspect the actual output for both. `GET /api/shorts/constants` returns shared dimensions, timing and safe-zone values.
- `POST /api/clips/{id}/metadata` accepts `tone`, optional `language`, and `cloud` (default false). Only explicit `cloud: true` sends up to 6,000 characters of clip transcript and the existing video title to Groq, then Gemini on failure. The video and paths are never sent. `GET` returns stored validated results. No keys or no cloud opt-in uses a basic local title. Provider failures leave prior metadata unchanged. Rendered metadata is also saved in `.txt` and `.metadata.json` sidecars. Configure existing `GROQ_API_KEY` / `GEMINI_API_KEY` in the backend environment, never in chat.
- `loop_polish: true` adds 100 ms visual/audio fades. Shorts ending snap uses punctuation and adds a 150 ms audio fade where a snap occurs. The local tail-energy score combines audible RMS and transcript timing; it is not speaker identification and may mistake background music for speech.

Re-check YouTube requirements against its current documentation. Real-world tracking, caption detection and cloud suggestions need human review.

### Cinematic letterbox

Set `layout: "letterbox"` explicitly; auto never selects it. `letterbox_bg` is a strict `#RRGGBB` colour (default `#000000`), `letterbox_vertical_bias` ranges from -0.15 to 0.15 of the canvas height (default +0.02), and `letterbox_edge` enables a one-pixel softened edge. The full source is fitted without tracking or cropping, with conditional upscaling sharpening. Exact 9:16 fills the canvas; narrower sources require side bars to preserve the full image and its aspect ratio. Jobs report `info.layout_used`, `info.video_rect`, `info.letterbox_bg` and, for an exact fill, `info.letterbox_note`. The preview path contains one full-source crop plus output `video_rect`, canvas dimensions and background colour.

`caption_position` can be `on_video` or `safe_zone`. Its default is on-video for letterbox and safe-zone otherwise. On-video placement attempts to fit a two-line block inside both the video and platform safe area, shrinking the font to no less than 70% before falling back; `info.caption_position_used` reports the choice when captions are enabled. Text size is estimated, so check actual fonts and rendered captions. SRT/VTT timing is unchanged.
